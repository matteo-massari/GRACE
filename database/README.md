# Local synthetic dataset
[Italiano](README.it.md)

This folder contains entirely fictitious and deterministic data, generated by
`pipeline/generate_synthetic_database.py`. The main CSV columns are
consistent with the transformations of `pipeline/ETL_fact.py` and `pipeline/ETL_recc.py`.

| File | Contents |
| --- | --- |
| `customers.csv` | 100 consumers and profile and dimensional attributes. |
| `salesreps.csv` | 30 sellers, districts, territories and macroregions. |
| `products.csv` | 60 products in the hierarchy `Level1`-`Level5`. |
| `customer_salesreps.csv` | Consistent assignment of each customer to a seller. |
| `purchases.csv` | Purchases at event level (10--100 per consumer). |
| `recommendations_placeholder.csv` | Placeholder top-10: it is not generated by GNN and has `source=placeholder_not_gnn`. |

`gnn/` contains the same base in the expected format from the GNN engine. To use it,
set `DATA_PATH=database/gnn`; GNN will find the dataset
`dataset_None_4_12`. GNN outputs are separated from placeholders and are not
overwritten by regeneration. CSVs generated and caches are excluded from Git.

Neo4j regeneration and loading:

```bash
make synthetic-data
make start-neo4j
make pipeline-synthetic
```

The loader uses `MERGE` to update the same entities without duplicating them; does not
automatically delete missing data from CSVs. To also import placeholder relationships
`RECOMMENDED_TO` (normally to leave to GNN), use:

```bash
uv run python pipeline/load_synthetic_neo4j.py --include-placeholder-recommendations
```

## GNN format

`gnn/training_tables/dataset_None_4_12/` contains:

| File | Main columns |
| --- | --- |
| `basket_data.csv` | `ids_customer`, `ids_product`, `dat` |
| `customer.csv` | `ids_customer`, `sector`, `potential`, `county`, `creditlimit` |
| `product.csv` | `ids_product` |
| `product_names.csv` | `ids_product`, `product_name` |

GNN retains the first purchase of each pair. Neo4j aggregates events instead
in the report `BUYS`, keeping count, quantity and before/last date.
The two representations start from the same base and serve different objectives.

CSV GNN appears only after inference, below `gnn/rec_tables/`. Regenerate the
data does not overwrite that output. For full flow see the
[operational guide](../docs/modules/getting_started.md).
